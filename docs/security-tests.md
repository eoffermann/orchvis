# Security tests

Where each security case from the plan's testing strategy (and the extra WP9 cases) is tested. Paths are relative to the repo root; names are the Vitest `describe > it` titles. Every test listed runs in `pnpm check`.

| Case | Expected behavior | Test file | Test |
|---|---|---|---|
| Forged channel tag in a body | Broker escapes `<channel` / `</channel` and strips control characters, in the delivered message and the UI feed | `packages/broker/test/routing.test.ts` | routing > escapes channel tags in the delivered message and in the UI feed |
| | Same, under random hostile fleet traffic | `packages/broker/test/simulator.test.ts` | broker driven by the WP1 simulator fleet > routes random fleet traffic with valid frames, and the live feed matches a fresh snapshot |
| | Shim escapes again before emitting | `packages/shim/test/channel.test.ts` | messageEvent > formats each attachment kind and sanitizes body and captions |
| | Shim emits the escaped body end to end | `packages/shim/test/integration.test.ts` | falls back to poll when the probe times out; inbox, Unread suffix, mirror file and seen |
| Forged channel tag in a caption or filename | Escaped in the delivered message and the UI feed | `packages/broker/test/media.test.ts` | media security > escapes forged channel tags in captions and filenames, in the delivered message and in the UI |
| | Web app renders hostile bodies, captions and filenames as text, creating no elements | `packages/web/test/overlays.test.tsx` | untrusted text is rendered as text only > shows hostile bodies, captions and filenames literally, creating no elements |
| A peer claiming to be the Owner | `from`, `senderKind`, `fromName`, `id`, `ts` come from the connection; payload claims are ignored | `packages/broker/test/routing.test.ts` | routing > a shim cannot appear as the owner or as another session |
| | The name `owner` cannot be taken by hello or register in any case; a session ID cannot be `owner`; `to: "owner"` always reaches the Owner | `packages/broker/test/security.test.ts` | a peer claiming to be the Owner > cannot take the name "owner" in any case, by hello or by register, and "owner" always means the Owner |
| | A shim cannot read Owner-only media, or attach the Owner's uploads | `packages/broker/test/media.test.ts` | GET /api/media/:id > answers 404 to a non-participant, a shim posing as the Owner, and anyone unauthenticated; attaching > lets the Owner attach its own uploads only, and sessions never attach the Owner’s |
| HTML and SVG uploads | Served as `attachment` downloads with `nosniff` and a sanitized filename, never inline | `packages/broker/test/media.test.ts` | GET /api/media/:id > serves HTML, SVG and other non-media types as attachments with a sanitized filename |
| | Declared image/audio/video whose bytes disagree is refused (415) | `packages/broker/test/media.test.ts` | POST /api/media > answers 415 when the content does not match the declared type |
| | Web app served with a CSP without inline script, and `nosniff` | `packages/broker/test/auth.test.ts` | static web app > serves a placeholder at / with the CSP and nosniff when there is no build |
| A missing token, on every authenticated endpoint | `POST /api/login` 400 and no cookie; `POST /api/media` 401 and nothing stored; `GET /api/media/:id` 404; `/ws/ui` 4401; `/ws/shim` hello without a token closed 4400; `POST /api/logout` without a cookie ends nothing | `packages/broker/test/security.test.ts` | a missing credential on every authenticated endpoint > fails safely everywhere, and logout without a cookie ends nothing |
| | Wrong or stale credentials: bad shim token, stale or replaced upload key | `packages/broker/test/registry.test.ts`, `packages/broker/test/media.test.ts` | /ws/shim hello > rejects a bad token with unauthorized and closes; POST /api/media > answers 401 without a token, with a wrong token, a stale key, or a replaced connection key |
| | `/ws/ui` without a cookie, with a forged one, or with a raw token as the cookie | `packages/broker/test/auth.test.ts`, `packages/broker/test/routing.test.ts` | /ws/ui upgrade > closes with 4401 without a cookie or with a forged one; /ws/ui auth > closes with 4401 for the raw owner or shim token in the cookie, and admits a login session |
| Cross-origin WebSocket upgrade | `/ws/ui` from another origin, a `localhost` alias, or with no Origin closes 4403, even with a valid cookie; Origin is checked before the cookie | `packages/broker/test/auth.test.ts` | /ws/ui upgrade > closes with 4403 for a cross-origin or Origin-less upgrade, even with a valid cookie |
| | Same decision as a unit | `packages/broker/test/units.test.ts` | UI auth > needs a matching Origin first, then a live session in the orchvis_owner cookie |
| Path traversal in an upload filename | Path parts dropped, `.` and `..` become `file`, a NUL fails the parse (400); the file on disk is named by its media ID only, and nothing is written outside the media directory | `packages/broker/test/security.test.ts` | path traversal > an upload filename never reaches the disk: only the media ID names the file, and the stored name is one plain component |
| Path traversal in the media ID on GET | Any ID with `..`, slashes, backslashes, NUL or an absolute path is 404 even for the Owner; encoded traversal in the raw URL never serves a file from outside | `packages/broker/test/security.test.ts` | path traversal > a media ID with path segments or dot-dot is 404 even for the Owner, and never reads outside the store |
| | Static files never escape the public directory | `packages/broker/test/auth.test.ts` | static web app > serves the build from publicDir, falls back to index.html for client routes, and never escapes the root |
| Oversized frame on `/ws/shim` | A frame over `maxPayload` (1 MiB; also when split into fragments), before or after hello, closes with 1009 without buffering it; the broker keeps serving and frees the link | `packages/broker/test/security.test.ts` | oversized WebSocket frames > /ws/shim closes with 1009 on a frame over maxPayload, before or after hello, and the broker keeps serving |
| Oversized frame on `/ws/ui` | Same, 1009 | `packages/broker/test/security.test.ts` | oversized WebSocket frames > /ws/ui closes with 1009 on a frame over maxPayload |
| | A frame under the cap but over the body limit is rejected `too_large`, and the connection stays | `packages/broker/test/security.test.ts` | oversized WebSocket frames > a frame under the cap but over the body limit is rejected as too_large and the connection stays |
| Owner cookie on `/ws/shim` or as a shim credential | `/ws/shim` ignores cookies; the Owner token, the cookie value or the cookie string as the hello token is `unauthorized`, 4400 | `packages/broker/test/security.test.ts` | Owner credentials are never shim credentials > /ws/shim ignores the Owner cookie and refuses the Owner token, the cookie value, or an empty token in hello |
| | The Owner token or cookie value in the shim media headers is 401/404, even beside a valid Owner cookie | `packages/broker/test/security.test.ts` | Owner credentials are never shim credentials > media endpoints refuse the Owner token or cookie value in the shim headers, even beside a valid Owner cookie |
| Secrets and bodies stay out of logs | No message body, token, upload key, cookie, caption or filename in broker logs | `packages/broker/test/lifecycle.test.ts`, `packages/broker/test/media.test.ts` | logging > never logs a message body or a token; media security > never logs tokens, upload keys, cookies, captions or filenames |
